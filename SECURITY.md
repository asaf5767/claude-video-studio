# אבטחה ופרטיות

הסטודיו רץ מקומית בלבד ומאזין רק לכתובת loopback,‏ 127.0.0.1; אין התחברות משתמשים, ואין להפעיל אותו מול חשיפה ציבורית — טאנל, פרוקסי הפוך או פתיחת חומת אש (שירות מתארח/צוותי דורש אימות, אחסון מדיה פרטי וסקירת פריסה נפרדים משלו). כל נקודת קצה שכותבת קבצים בודקת כותרת Host מקומית מדויקת, כותרת Origin מדויקת וכותרת X-Studio-Action; מדיה והערות רשומות מוגבלות לתיקיות projects/<slug> או references/<slug> בלבד (כולל בדיקות symlink וגבולות נתיב), וקבצים סטטיים מוגשים רק מתוך dist.

שני נתיבי ההעלאה המקומיים היחידים: PUT /materials (חומרי גלם, עד 8GB) ו-PUT /inspiration-file (סרטוני השראה, mp4/mov/webm/m4v בלבד, עד 1GB) — עם אותם שומרים, זרימה לקובץ זמני עם בדיקת Content-Length מדויקת, ומעבר למקום הסופי רק בהצלחה. אין API להרצת קוד שרירותי. פתיחת העורך (HyperFrames) דורשת POST מאובטח מפורש ומריצה כלי שורת-פקודה קבוע בלי shell; בקשת GET לעולם לא מריצה תהליכים. שליפת תמונת-נושא חיצונית (reference-preview) מקבלת HTTPS בלבד, דוחה כתובות DNS שאינן ציבוריות, מצמידה את החיבור לכתובת שנבדקה תוך אימות TLS מול שם המארח המקורי (הגנה מפני DNS rebinding), ובודקת מחדש כל הפניה (redirect); היא לעולם לא טוענת סקריפטים, embeds, עוגיות או וידאו. פתיחת העורך לעולם לא משנה סקירה שמורה, לא מאשרת אותה ולא מרנדרת גרסה סופית. שמירת סרטון השראה חדש מתמזגת תחת נעילת הקטלוג: כפילות לא דורסת הערות קיימות, ועריכה דורשת את הגרסה הנוכחית של הרשומה.

הכפתור "שליחה לקלוד" מריץ את Claude Code בלי השגחה. כך זה מוגן, בלי הבטחות שאי אפשר לעמוד בהן:

- **בזמן שקלוד קורא תוכן של אחרים, אין לו טרמינל.** "ללמוד את הסגנון" היא המשימה היחידה שקוראת תוכן של יוצר אחר (סרטון, מילים, טקסט על המסך). את התמלול, זיהוי החיתוכים, תמונות המפתח ומדידת העוצמה עושה השרת של הסטודיו לפני שקלוד מופעל, בפקודות קבועות. בזמן הריצה הזו לקלוד אין טרמינל: הוא יכול לקרוא רק את התיקייה של אותה השראה, ולכתוב רק את style-card.md (זיכרון אוטומטי ו-hooks כבויים).
- **הערוץ שנשאר הוא צר, לא סגור.** המראה שקלוד לומד מהסרטון (שורות טקסט קצרות שנבדקו, עד 300 תווים כל אחת, בלי תווי בקרה) מועתק על ידי הסטודיו לקובץ look.json בתיקיית הסרטון שלכם, ונקרא אחר כך בריצות על החומרים שלכם, שבהן יש טרמינל. הערכים האלה הם טקסט, והכישורים מתייחסים אליהם כאל חומר עבודה ולא כאל הוראות, אבל טקסט שנכתב בעקבות סרטון זדוני עדיין יכול להטעות את המודל.
- **ריצה על החומרים שלכם** (מדבר למצלמה, בלי פנים) משתמשת בטרמינל דרך סקריפטי העזר של הסטודיו. סביבם יש כמה שכבות הגנה: כללי ההרשאות של Claude Code, סקריפטי עזר שדוחים כל נתיב מחוץ לתיקיית הסרטון (חוץ מקריאה של תיקיות המראות, האפקטים והתבניות של הסטודיו, שהן לקריאה בלבד), עטיפה ל-ffmpeg שמתירה רק אפשרויות ומסננים מוכרים, ובדיקה לפני כל ריצה ואחריה שקבצי הסטודיו עצמו לא השתנו. אלה הגנות לעומק שבודקות טקסט של פקודות ונתיבים. הן לא ארגז חול, וייתכן שיש דרך לעקוף אותן.
- **בווינדוס אין ארגז חול של מערכת ההפעלה** לריצה כזו, ובמק הסטודיו לא מפעיל אותו. כל ריצה פועלת עם ההרשאות של המשתמש שלכם.
- **מפתחות.** המפתחות היחידים שהסטודיו שומר הם של התוספות האופציונליות (ElevenLabs, OpenAI Images), בקובץ ‎.env‏. אם לא הפעלתם תוספת, אין שם מפתח לגנוב. ההתחברות של Claude Code עצמו נשמרת אצל Claude Code, לא בסטודיו.
- **מה הבדיקה של קבצי הסטודיו לא תופסת:** שינוי שנעשה והוחזר למצבו לפני סוף הריצה, ושינוי שנעשה מחוץ לסטודיו (תוכנה אחרת או מחשב פרוץ).

אישורי סקירה שומרים מטא-דאטה בלבד (גרסה/hash נוכחיים ויומן היסטוריה) — זו לא הגנה מפני מחשב פרוץ או תהליך מקומי זדוני. מפתחות API וסודות אחרים נשמרים רק בקובץ .env המקומי — לעולם לא מחויבים ל-git ולעולם לא נשלחים לדפדפן; וכך גם העדפות כתיבה ותקצירי סקריפט — נתוני בעלים בלבד, לעולם לא נשלחים לשירות מודל חיצוני. לעולם אין להעלות קטלוגים אמיתיים, חומרי גלם, הערות, פרויקטים או credentials ל-git — יש להשתמש ב-release-files.txt והמייצא המפורש בלבד; ‎.gitignore‏ לבדו אינו ביקורת פרטיות.

כדי לדווח על חשש אבטחה, פתחו Issue בגיטהאב בפרויקט [asaf5767/claude-video-studio](https://github.com/asaf5767/claude-video-studio). אין לפרסם מדיה פרטית, פרויקטים אמיתיים, מפתחות או סודות ב-Issue פומבי.

# Security and privacy

The studio is local-only: it binds exclusively to the 127.0.0.1 loopback address, has no user login, and must never run behind a public tunnel, reverse proxy or opened firewall (a hosted/team service needs its own separate authentication, private media storage and deployment review). Every write endpoint checks an exact local Host header, an exact Origin header and an X-Studio-Action header; registered media and notes are confined to the projects/<slug> or references/<slug> directories only (including symlink and path-boundary checks), and static files are served from dist alone.

There are exactly two local upload routes: PUT /materials (raw footage, up to 8 GiB) and PUT /inspiration-file (reference videos, mp4/mov/webm/m4v only, up to 1 GiB) — both with the same guards, streamed to a temp file with an exact Content-Length check and moved into place only on success. There is no arbitrary-code API. Opening the editor (HyperFrames) requires an explicit guarded POST and runs a fixed local CLI without a shell; a GET request never launches a process. The external cover-image fetch (reference-preview) accepts HTTPS only, rejects non-public DNS results, pins the connection to the checked address while verifying TLS for the original hostname (a DNS-rebinding defence), and rechecks every redirect; it never loads scripts, embeds, cookies or video. Opening the editor never modifies a saved review, approves it or renders a final. Saving a new reference merges under the catalog lock: a duplicate never overwrites existing notes, and an edit requires the entry's current revision.

"Send to Claude" runs Claude Code unattended. This is how it is protected, without claims we cannot back:

- **While Claude reads other people's content, it has no shell.** "Learn this style" is the only job that reads another creator's content (their video, words and on-screen text). The studio's own server does the transcription, cut detection, key frames and loudness measurement first, with fixed commands, before Claude starts. During that run Claude has no shell: it can read only that reference's folder and write only style-card.md (auto memory and hooks are off).
- **What remains is a narrowed channel, not a closed one.** The look Claude learns from that video (short checked text values, at most 300 characters each, control characters removed) is copied by the studio into look.json in your video's folder, and later read by runs on your own material, which do have a shell. Those values are text and the skills treat them as material, not instructions, but text written from a malicious video could still mislead the model.
- **Runs on your own material** (talking head, faceless) use a shell through the studio's helper scripts. Around them are several layers: Claude Code's permission rules, helpers that refuse any path outside the video's folder (except reading the studio's own looks, effects and templates folders, which are read-only), an ffmpeg wrapper that allows only known options and filters, and a check before and after every run that the studio's own files did not change. These are defence in depth that check command and path text. They are not a sandbox, and a way around them may exist.
- **Windows has no operating-system sandbox** for such a run, and on a Mac the studio does not turn one on. Every run works with your own user's permissions.
- **Keys.** The only keys the studio stores are for the optional add-ons (ElevenLabs, OpenAI Images), in .env. If no add-on is turned on, there is no key there to steal. Claude Code's own sign-in is kept by Claude Code, not by the studio.
- **What the studio-files check does not catch:** a change made and undone before the run ends, and a change made outside the studio (another program or a compromised machine).

Review approvals record metadata only (the current version/hash and a history journal) — this is not protection against a compromised machine or a malicious local process. API keys and other secrets live only in the local .env file — never committed to git, never sent to the browser — and the same goes for writing preferences and script briefs: owner data only, never sent to an external model service. Never commit real catalogs, footage, notes, projects or credentials to git; use release-files.txt and the explicit exporter only — .gitignore alone is not a privacy audit.

To report a security concern, open an issue on GitHub at [asaf5767/claude-video-studio](https://github.com/asaf5767/claude-video-studio). Never post private media, real projects, keys or other secrets in a public issue.
